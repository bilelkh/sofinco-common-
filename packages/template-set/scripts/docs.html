Générateur de Composants Sofinco Pour Tous

👋 En résumé : Ce script génère automatiquement toute l'architecture d'un composant Jahia + React en une seule commande. Il pose 4 à 5 questions et crée entre 8 et 10 fichiers parfaitement connectés — zéro erreur humaine, respect strict des conventions du projet.

1. Lancement Devs

Depuis la racine du projet (monorepo) :

npm run make:component
# ou
yarn run make:component
💡 Dépannage : Si le terminal affiche une erreur, installez l'exécuteur TypeScript : yarn add -D tsx ou npm install -D tsx.

2. Flow de questions

Le script pose les questions dans cet ordre. Chaque réponse est formatée automatiquement (PascalCase, camelCase) — vous pouvez écrire hero-banner, HeroBanner ou hero_banner, le résultat est identique.

Nom du composant
Ex : EventsListDemo, hero-section, SeoMesh
Périmètre de marque Nouveau
sofinco-react/src est cloisonné par marque — le composant est déposé dans un seul de ces dossiers :
[1] b2c → src/b2c/features/  ·  [2] b2b → src/b2b/features/  ·  [3] common → src/common/ (rendu par les deux marques).
Par défaut : b2c.
Domaine / Groupe parent
Regroupe plusieurs composants sous un dossier commun avec un index.ts de barrel.
Ex : tapez Footer pour créer src/b2c/features/Footer/FooterLogo/.
Laissez vide pour un composant indépendant.
Sous-dossiers ? (y/n) — affiché uniquement si le nom contient plusieurs mots
Si votre composant s'appelle EventsList, le script propose de créer Events/List/ au lieu d'un seul dossier EventsList/.
Stratégie d'interface serveur Nouveau
[1] OCP — Génère une interface *PropsServer extends *Props dédiée. Idéal quand la vue serveur aura des props supplémentaires (labels edit-mode, nodes JCR enfants).
[2] YAGNI — Pas d'interface serveur. Client et serveur partagent la même *Props. Idéal pour les composants simples qui ne différencient pas les deux contextes.
Traductions / i18n ? Nouveau
[y] — Conserve useAppTranslation et ajoute t? en paramètre optionnel dans toutes les fonctions de mapping.
[n] — Supprime useAppTranslation et le paramètre t de tous les fichiers générés. Pour les composants sans texte traduit.

Exemple de session complète

> Nom du composant : EventsListDemo
> Nom Domain Groupe Component : Events
> Diviser en sous-dossiers (Events/List/Demo) ? (y/n) : n

📐 Stratégie d'interface serveur :
[1] OCP — PropsServer extends Props
[2] YAGNI — Props partagés Client/Serveur
> Votre choix (1 ou 2) : 1

🌐 Utiliser les traductions (useAppTranslation / t) ?
[y] Oui — t? optionnel dans les mappings
[n] Non — useAppTranslation et t supprimés
> Votre choix (y/n) : n

🚀 Génération de EventsListDemo...
🏷️ Périmètre : b2c
📁 Domaine : Events
📍 Import généré : sofinco-react
📐 Stratégie : OCP (PropsServer)
🎉 Architecture Client/Serveur générée avec succès !

3. Fichiers générés

⚛️ Package sofinco-react — Interface visuelle (identique dans toutes les stratégies)
[nom].types.ts

Interface *Props du composant React pur. Définit les données attendues (titre, URL, etc.). C'est le contrat de données partagé entre les deux packages.

[Nom].tsx

Le composant React principal — "stupide" : il affiche uniquement ce qu'on lui passe, sans savoir d'où vient la donnée.

[nom].module.css

Styles isolés du composant (CSS Modules).

index.ts

Barrel export du composant. Si un domaine est défini, le script met aussi à jour le index.ts du domaine et le src/index.ts racine — automatiquement, sans doublon.

⚙️ Package sofinco-template — Couche Jahia (varie selon la stratégie)
definition.cnd

Plan JCR du composant. Déclare le type de nœud Jahia (sofnt:monComposant) et les champs éditables dans le back-office.

[nom].types.ts OCP uniquement

Déclare *PropsServer extends *Props. Permet d'ajouter des props exclusifs au serveur (nodes JCR, labels edit-mode) sans toucher à l'interface React. Non généré en mode YAGNI.

[nom].mapping.ts

Traduit un nœud JCR brut en objet Props utilisable par React.
OCP : deux fonctions — map*PropsClient(node) et map*PropsServer(node).
YAGNI : une seule fonction — map*Props(node).
Si i18n activé, t? est ajouté comme paramètre optionnel.

[nom].render.tsx

Abstraction du rendu. Expose render*Client(props) (Island hydration) et render*Server(props) (rendu direct). Le default.server.tsx n'instancie jamais de JSX directement, il passe toujours par ce fichier.

default.server.tsx

Point d'entrée Jahia — enregistre le composant via jahiaComponent().
OCP : appelle map*PropsServer en edit-mode et map*PropsClient en live.
YAGNI : appelle une seule fois map*Props, puis choisit le render selon isEdit.
Si i18n désactivé, useAppTranslation et const { t } sont absents.

views/[Nom]Server.tsx

Vue rendue uniquement en mode édition Jahia (Page Composer). Conçue pour accueillir les boutons AddContentButton et les RenderChildren Jahia. Reçoit *PropsServer (OCP) ou *Props (YAGNI).

views/[Nom]Client.client.tsx

Composant hydratable côté navigateur. Enveloppe le composant React pur pour l'architecture Islands de Jahia. Reçoit toujours *Props (sérialisable).

views/[nom].module.css

CSS exclusif à la vue serveur (edit-mode). Utile pour mettre en valeur les zones éditables dans le Page Composer.

5. Option i18n — Traductions Nouveau

Élément i18n = y (avec traductions) i18n = n (sans traductions)
Import dans default.server.tsx import { useAppTranslation } from "#lib/i18n" Absent
Corps de la fonction dans default.server.tsx const { t } = useAppTranslation(); Absent
Signature des fonctions dans mapping.ts map*Props(node, t?: (key: string) => string) map*Props(node)
Appel dans default.server.tsx map*Props(currentNode, t) map*Props(currentNode)
💡 Pourquoi t? optionnel et non obligatoire ?
Rendre t optionnel permet d'appeler les fonctions de mapping dans des contextes sans i18n (tests unitaires, scripts de migration) sans avoir à passer un mock. C'est un choix de flexibilité qui n'impacte pas la type-safety à l'usage normal.

6. Configuration globale Devs

En haut du fichier generate-component.ts, une seule constante contrôle le style d'import pour tous les fichiers générés par toute l'équipe :

// generate-component.ts — ligne 15
const IMPORT_STYLE: ImportStyle = 'A';
ValeurImport généréUsage
'A' (défaut) import { Hero } from "sofinco-react" Simple, recommandé. Tree-shaking géré par le bundler.
'B' import { Hero } from "sofinco-react/Hero/Banner" Import précis par chemin. Utile si le package n'est pas configuré pour l'export racine.

7. Comportement Fail-Safe

Le script ne peut pas écraser un fichier existant. Si vous relancez le générateur sur un composant déjà créé :

✅ Créé : footer.mapping.ts
⏩ Ignoré : footer.types.ts (Existe déjà)
⏩ Ignoré : default.server.tsx (Existe déjà)

Cela permet d'ajouter un sous-composant dans un domaine existant sans risque d'écraser du travail déjà effectué.

💡 Astuce : Les index.ts de barrel sont mis à jour par append (ajout en fin de fichier) — jamais réécrits. Un export déjà présent n'est jamais dupliqué.
