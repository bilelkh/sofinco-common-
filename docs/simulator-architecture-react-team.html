🤔 Pourquoi ce refactor ?

Le helper Jahia buildSimulatorCtaUrl produit des URLs avec hash Vue.js (#/montant-financement), mais le navigateur strippe le hash lors d'un form GET natif.

Avant le refactor

<form action="/path?p=X#/route">
Submit natif → navigation vers /path?amount=150
→ params perdus, hash perdu

Après le refactor

onSubmit handler intercepte → reconstruit l'URL :
/path?p=X&amount=150#/route
→ tout préservé
Bénéfice secondaire : factorisation de la logique form submit entre HeroSimulator et SimulatorBlock via un helper partagé (DRY).

🆕 Fichiers NOUVEAUX

packages/sofinco-react/src/shared/utils/simulatorFormSubmit.ts
NEW

Rôle

Factory function pure qui crée un handler onSubmit réutilisable pour tous les formulaires simulateur Sofinco. Mutualise la logique de préservation du hash route Vue.js.

API exportée

export interface SimulatorFormSubmitOptions {
  ctaHref?: string;   // URL complète, possiblement avec hash route
  ctaTarget?: string; // "_blank" → window.open ; sinon location.href
}

export function createSimulatorFormSubmitHandler(
  opts: SimulatorFormSubmitOptions
): (e: FormEvent<HTMLFormElement>) => void

Comportement

  • ctaHref vide → return immédiat (no preventDefault → soumission native)
  • Pas de hash dans ctaHref → return immédiat (rien à préserver)
  • Hash présent → preventDefault + reconstruction URL avec params form + hash
  • target=_blank → window.open(url, "_blank", "noopener,noreferrer")
  • target autre → window.location.href = url
packages/sofinco-react/src/shared/utils/simulatorFormSubmit.test.ts
NEW

5 tests unitaires

  1. no-op quand ctaHref est vide — preventDefault non appelé
  2. laisse passer la soumission native quand pas de hash
  3. intercepte le submit et réinjecte le hash après les params (amount inclus)
  4. hash sans query existante → ajoute ? puis params puis hash
  5. target=_blank → window.open avec noopener,noreferrer

Diff structurel

AVANT — callback pattern

const SimulatorBlock = ({
  ...,
  cta,
  onSimulate,
}) => {
  const handleSubmit = (e) => {
    e.preventDefault();
    const input = e.currentTarget
      .elements.namedItem("amount");
    onSimulate(Number(input.value));
  };

  return <form onSubmit={handleSubmit}>
    ...
    <Cta {...cta} type="submit" />
  </form>;
};

APRÈS — href + handler partagé

const SimulatorBlock = ({
  ...,
  cta,  // CtaProps avec href + label + target
}) => {
  const ctaHref = cta?.href ?? "";
  const ctaTarget = cta?.target;
  const handleSubmit =
    createSimulatorFormSubmitHandler({
      ctaHref, ctaTarget,
    });

  return <form
    action={ctaHref}
    method="GET"
    target={ctaTarget}
    onSubmit={handleSubmit}
  >
    ...
    <Cta label={buttonLabel}
         type="submit" />

⚠️ Breaking changes — résumé

SimulatorBlock — API React DS

Si une autre app (mobile, BO Sofinco, partenaire) consomme <SimulatorBlock>, elle doit migrer :

  • onSimulate prop : SUPPRIMÉE
  • cta prop : type changé de { label: string } à CtaProps | null
  • Nouvelle responsabilité : passer cta.href contenant l'URL cible complète

HeroSimulator — pas de breaking

Le contrat de HeroSimulator n'a pas changé. Seul l'interne a été modifié pour ajouter le handler de hash preservation. Aucune migration nécessaire pour les consommateurs.

📦 Guide de migration consommateurs externes

Pour les consommateurs externes du DS qui utilisaient l'ancien contrat callback :

AVANT — pattern callback

<SimulatorBlock
  title={titleProps}
  amountPlaceholder="Montant"
  amountMin={500}
  amountMax={50000}
  cta={{ label: "Calculer" }}
  onSimulate={(amount) => {
    const url =
      `/sim?amount=${amount}`;
    window.location.href = url;
  }}
/>

APRÈS — pattern href

<SimulatorBlock
  title={titleProps}
  amountPlaceholder="Montant"
  amountMin={500}
  amountMax={50000}
  cta={{
    label: "Calculer",
    href: "/sim#/montant",
    target: "_self",
    ctaSection: "my-app-cta",
    variant: "accent",
  }}
/>
// Le DS injecte &amount=X au submit
// + préserve #/montant via onSubmit
Avantage migration : plus besoin d'écrire de callback navigation custom. Le DS gère seul : validation input, prévention min>max, hash preservation, target=_blank, fallback JS désactivé.

🎯 Synthèse des bénéfices

DRY

Une seule implémentation du submit handler (factory partagée). Bug fix = 1 endroit.

Cohérence DS

HeroSimulator et SimulatorBlock partagent le même contrat (CtaProps) et le même comportement (hash preservation).

Storybook réaliste

Stories avec vraies URLs au lieu de mock callbacks → l'équipe DS voit ce que la prod voit.

Accessibilité

Form HTML standard avec action — fonctionne sans JS (graceful degradation).

Type safety

CtaProps typé exporté du DS — autocomplétion + erreurs compile-time côté consommateurs.

Code template-set allégé

Plus de URL builder custom (simulatorUrl.ts obsolète), plus d'Island wrapper sur SimulatorCredit.
